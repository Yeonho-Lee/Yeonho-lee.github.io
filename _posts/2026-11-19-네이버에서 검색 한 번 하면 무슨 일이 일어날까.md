얼마 전 커피챗에서 "브라우저에서 네이버에 들어가 검색을 하면 무슨 일이 일어날까?"라는 이야기가 나왔다. 매일 프론트엔드 코드를 짜면서도 실제로 무슨 일이 일어나는지 자세하게 설명하려니 생각보다 어려웠다. 그래서 이번 기회에 큰 흐름부터 정리해 본다.

> 💡 이 글은 전체 흐름만 훑는다. 네트워크와 DB는 다음 글에서 하나씩 자세히 다룬다.

## 전체 흐름 한눈에 보기

```
[브라우저] 서버에 첫 페이지 요청 (naver.com)→ HTML/CSS/JS 받아서 렌더링
    ↓ 사용자가 검색어 입력 + 검색 버튼 클릭 (이벤트)
[프론트엔드] 백엔드에 검색 요청 전송
    ↓ 네트워크 (HTTP)
[백엔드] 요청을 받아 DB에 쿼리
    ↓
[DB] 데이터 반환
    ↓
[백엔드] 응답 전송
    ↓ 네트워크 (HTTP)
[프론트엔드] 응답을 받아 화면에 표시
```

## 1. 브라우저가 첫 페이지를 가져와 렌더링한다

주소를 입력하면 브라우저는 서버에 "첫 화면 주세요"라고 **요청**을 보내고, 응답으로 받은 HTML, CSS, JavaScript로 화면을 그린다. 우리가 보는 네이버 첫 화면이 이 단계의 결과다.

눈여겨볼 점은, 첫 화면을 가져오는 것 자체가 이미 **요청 → 응답** 한 번이라는 거다. 뒤에서 볼 검색 요청과 같은 방식으로 오간다.

> 💡 사실 그 전에 도메인(`www.naver.com`)을 IP 주소로 바꾸는 DNS 조회, 서버와 연결을 맺는 과정도 있지만 이 글에서는 생략한다.

## 2. 사용자가 검색한다

검색창에 검색어를 입력하고 버튼을 누르면 **이벤트**가 발생한다. 프론트엔드 코드는 이 이벤트를 감지해서 "검색해줘"라는 요청을 준비한다.

## 3. 프론트엔드가 백엔드에 API 요청을 보낸다

여기서 **API(Application Programming Interface)** 가 등장한다. API는 프론트엔드와 백엔드가 서로 대화하기 위해 정해둔 **약속(인터페이스)** 이다. "이 주소로, 이런 형식으로 요청하면, 이런 형식으로 답해줄게" 같은 규칙이다.

```ts
const res = await fetch('/api/search?q=svelte');
const data = await res.json();
```

> 💡 개념 설명을 위해 단순화한 예시다. 실제 네이버는 검색 버튼을 누르면 `search.naver.com/search.naver?query=...` 페이지로 **이동**하고, 서버가 결과가 담긴 HTML을 통째로 만들어 보내준다. 위처럼 `fetch`로 데이터만 받아오는 방식은 검색어 자동완성 같은 곳에 더 가깝다. 어느 쪽이든 "요청을 보내고 응답을 받는다"는 흐름은 같다.

API를 설계하는 대표적인 방식 중 하나가 **REST**이고, REST의 원칙을 잘 지킨 API를 **RESTful API**라고 부른다. 이건 다음 글에서 자세히 다룬다.

## 4. 백엔드가 DB에서 데이터를 가져온다

요청을 받은 백엔드는 DB에 **쿼리**를 보내 필요한 데이터를 가져온다.

```sql
SELECT title, url FROM documents WHERE title LIKE '%svelte%';
```

> 💡 이것도 개념 설명용이다. 실제 검색 엔진은 `LIKE`로 매번 전체를 훑지 않고, 미리 만들어 둔 검색용 인덱스를 사용한다.

## 5. 프론트엔드가 응답을 받아 화면에 띄운다

백엔드가 보내준 응답(보통 JSON)을 받아서 검색 결과 목록을 화면에 그린다. 여기까지가 한 사이클이다.

## SvelteKit에서는 어디에 해당할까

평소 내가 쓰는 SvelteKit 프로젝트에 대입해 보면 이렇다.

| 단계          | SvelteKit에서                                                                                                              |
| ----------- | ------------------------------------------------------------------------------------------------------------------------ |
| 렌더링, 이벤트 처리 | `+page.svelte` 컴포넌트                                                                                                      |
| API 요청 / 응답 | [Remote Functions]({% post_url 2026-03-10-SvelteKit Remote Functions - 서버 호출이 이렇게 쉬워진다고 %}) (`query`, `command`, `form`) |
| DB 쿼리       | [Drizzle ORM]({% post_url 2026-03-16-한글로 DB테이블,컬럼명을 지정할 수 있다고 %}) + SQLite                                               |

평소에 당연하게 쓰던 것들이 사실 이 흐름의 한 조각씩을 맡고 있었다.

### 코드로 옮겨 보면

학생 이름을 검색하는 작은 예제로 위 흐름을 그대로 옮겨 봤다. 주석의 번호가 위 단계와 같다.

```ts
// src/routes/search/search.remote.ts
import { query } from '$app/server';
import * as v from 'valibot';
import { like } from 'drizzle-orm';
import { db } from '$lib/server/db';
import { students } from '$lib/server/db/schema';

// ④ 백엔드: 요청을 받아 DB에 쿼리
export const searchStudents = query(v.string(), async (keyword) => {
  return db
    .select()
    .from(students)
    .where(like(students.name, `%${keyword}%`));
});
```

```svelte
<!-- src/routes/search/+page.svelte -->
<script lang="ts">
  import { searchStudents } from './search.remote';

  // ② 사용자 입력 (이벤트)
  let keyword = $state('');
</script>

<input bind:value={keyword} placeholder="이름 검색" />

<!-- ③ 요청 → ⑤ 응답을 받아 화면에 표시 -->
{#each await searchStudents(keyword) as student (student.id)}
  <p>{student.name}</p>
{/each}
```

① 첫 페이지를 렌더링하는 건 SvelteKit이 해주고, 우리가 쓴 코드는 ②~⑤에 해당하는 이 두 파일이 전부다. 검색창에 `홍`을 입력하면 `홍길동`, `홍길순`이 화면에 나온다.

③에서 프론트엔드와 백엔드가 주고받는 요청이 정확히 어떻게 생겼는지는 다음 글에서 들여다본다.
